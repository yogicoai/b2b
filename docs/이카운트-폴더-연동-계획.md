# 이사님(jay) 이카운트 폴더를 앱에 그대로 가져오기 — 실행 계획

> 2026-09-16 조사. **아직 실행하지 않았다.** 아래 "먼저 정해야 할 것"에 답이 나온 뒤에 착수한다.
> 조사 근거: 4갈래 코드·DB·IMAP 실측 + 3갈래 적대적 검토.

## 왜 하는가

이사님은 이카운트 웹메일에서 **본인 방식으로 폴더를 나눠 쓰고 계신다.** 그런데 앱은 그걸
한 통도 못 보고 있고, 대신 발신 도메인에서 기계적으로 지은 이름(`Bucketplace`, `Coupang`,
`Osstempharma`)으로 따로 분류하고 있다. 도구가 쓰는 사람의 업무 구조를 따라가야 한다.

| | 이카운트 실제 | 앱 화면 |
|---|---|---|
| jay | Yogibo Inc 275 · Yogibo LLC 18 · 인수인계서 3 · 신사업 0 · 중요메일함 0 | · 광고·자동발송 162 · · 사내 154 · ㈜베스코해운항공 21 · · 기타 17 … |
| 겹치는 이름 | **0개** | |

hjs 계정은 직접 만든 폴더가 없다(시스템 폴더 5개뿐) → 화면 변화 없음.

## 막히는 곳 (한 군데가 아니다)

| # | 위치 | 증상 |
|---|---|---|
| 1 | `ingest.ts` `isGroupFolder` | `INBOX.` 로 시작해야 거래처 폴더로 인정. 이카운트는 `Yogibo Inc` 처럼 **최상위 평면 경로**로 준다 → 항상 false |
| 2 | `ingest.ts` runIngest 대상 폴더 | `['INBOX', ...imapFolders]` 인데 `imapFolders` 가 빈 배열. **이 값을 채우는 코드가 앱 전체에 없다** |
| 3 | `imap.ts` SEARCH SINCE | 60일 창으로 찾는데 5개 폴더 메일이 전부 60일 밖(Yogibo Inc 최신 2025-08-11) → 0통 |
| 4 | `groups.ts` getFolderOrder | `group === folder` 면 continue. `Yogibo Inc` 는 이름이 안 바뀌어 **항상 continue** → 빈 폴더가 영영 안 뜸 |
| 5 | `auto-folder/route.ts` | 자동 분류가 폴더 분류를 덮어씀 |

**5번은 이미 막아 뒀다** (이 커밋). 나머지는 미착수.

## 이미 넣어 둔 방어막 (2026-09-16)

폴더를 실제로 가져오기 **전에** 넣어야 의미가 있는 것들만 먼저 적용했다.
지금은 `groupBy:'folder'` 메일이 0통이라 동작 변화가 없지만, 없으면 나중에 되돌릴 수 없다.

- `auto-folder/route.ts` · `groups/route.ts` — `groupBy: { $nin: ['manual','folder'] }`
  (기존엔 `manual` 만 빠져서 `folder` 가 덮였다). projection 에 `groupBy` 도 추가.
- `scripts/prune-old-mail.mjs` — keepFilter 에 `groupBy in ['folder','manual']` 와
  `group` 비어있지 않음 추가. **적대적 검토가 지목한 진짜 복구 불가 지점**이다.
  거래처 폴더 아카이브는 애초에 60일 밖이라, 보호가 없으면 들여오는 족족 삭제 후보가 된다.

## 먼저 정해야 할 것 (이사님/사용자 결정)

1. **60일 보관 규칙을 깰 것인가**
   - 깨면: 294통(다운로드 349.6MB)이 들어와 `Yogibo Inc 273` 이 뜬다. DB 는 5.8MB→7.3MB (512MB 중 1.4%). 용량은 문제 없음.
   - 안 깨면: **폴더 이름 5개만 뜨고 통수는 전부 0.**
2. **`인수인계서`·`신사업`·`중요메일함` 은 거래처가 아니라 주제 폴더다.** 진짜 거래처와 같은 층에 세울 것인가?
3. **`Yogibo Inc`·`Yogibo LLC` 는 계열사다.** 폴더명 그대로 거래처로 쓰면 B2B 리드 집계에 계열사가 외부 거래처처럼 섞인다.
4. 폴더를 서버가 전부 자동 발견할 것인가, 빼는 UI(skipFolders)를 만들 것인가? → 자동 발견만으로 목표 달성. 끄기 UI 는 나중에.

## 실행 순서 (검토 반영 후)

1. **학습 오염 차단을 먼저** — `getOwnDomains()` 로 자사 도메인 제외. 이게 없으면 백필 직후 `· 사내` 298통이 `Yogibo Inc` 로 통째로 빨려 들어간다. 학습 경로에는 날짜 필터가 없어 즉시 반영된다.
2. 폴더 판정을 `groups.ts` 한 곳으로 모으고 시스템 폴더(한글 포함)를 전부 커버
3. `ingest.ts` 의 지역 `isGroupFolder`/`groupNameFromFolder` 삭제 → `groups.ts` 것 사용
4. `groups.ts` getFolderOrder 의 `group === folder` 조건을 `isGroupFolder(folder)` 로
5. 폴더 목록을 **열린 연결 안에서** `listMailboxes(scoped)` 로 라이브 발견 + `imapFolders` 캐시(변경 시에만 저장)
6. SEARCH SINCE 를 폴더별 분기 — `isGroupFolder(folder) ? null : sinceDate`.
   ⚠️ **INBOX 에는 절대 null 금지** (이 서버는 SEARCH 결과를 자른다: exists 19,346 vs SEARCH ALL 5,150)
7. 백필 먼저, 평상시 수집은 그 다음
8. 백필 1회차는 리드 자동매칭 끄기 — 2022~2025 메일이 Lead 의 `lastInboundAt`/`needsReply` 를 몇 년 전 날짜로 덮는다

## 적대적 검토가 잡아낸 것 (계획의 오류)

- **계획이 '복구 불가'라 한 두 가지는 과장이다.** 294통은 auto-folder 의 2개월 창 밖이라 애초에 대상이 아니고, 백필은 `lastUid` 가 아니라 자체 커서를 써서 순서가 꼬여도 재실행으로 복구된다.
- **진짜 복구 불가는 `prune-old-mail.mjs`** 였다 → 이번에 막아 뒀다.
- **백필 실제 총량은 jay 1.55GB** (계획서 349.6MB 의 4.4배). INBOX 1,202.8MB 를 안 셌기 때문. → **INBOX 를 빼고 5개 폴더만** 돌 수 있게 해야 한다. 목표와 무관한 비용이 전체의 77%.
- `batchSize` 를 낮출 API 통로가 없다. 배치 최대 132MB, 단일 메일 최대 33.7MB → 크기 가드 필요.
- 재배치(refile) 를 넣을 땐 `accountId` 를 반드시 필터에 넣을 것. 없으면 hjs 문서에 jay 의 folder/uid 가 박혀 본문·첨부가 안 열리는 '유령 메일' 이 된다.
- `app.js` 가 로그인 즉시 수집을 돌리므로 "백필 먼저" 순서는 강제할 수단이 없다.
