# 리드 자동 검증 방법론

> CRM에 등록된 업체(리드) 데이터의 정합성을 자동으로 점검해, "의심 업체"를 시각적으로 분류하는 기능입니다. 외부 유료 서비스 없이 무료로 동작하며, 빠르게 1차 필터링 후 사람이 의심 케이스만 검토할 수 있게 합니다.

---

## 1. 검증하는 항목 (4가지)

각 리드에 대해 아래 4가지를 자동 점검하고, **0~4점 점수**를 매깁니다.

| 항목 | 무엇을 확인하나 | 방법 |
|---|---|---|
| **이메일** | 메일이 도달 가능한 진짜 도메인인지 | (a) 문법 정규식 → (b) 도메인 MX(메일 서버) 레코드 DNS 조회 → (c) 일회용 메일 도메인 블랙리스트 |
| **웹사이트** | 사이트가 실제로 살아있는지 | HEAD 요청 (6초 타임아웃) → 일부 서버가 HEAD 차단 시 GET 폴백. 200~399 응답이면 alive |
| **전화번호** | 입력된 번호의 국가코드가 Country 컬럼과 일치하는지 | 숫자 추출 → 알려진 국가 다이얼링 코드 매칭. 예: `Country=Korea`인데 `Phone=+86...` 이면 불일치 |
| **LinkedIn** | LinkedIn URL이 표준 형식인지 | `linkedin.com/in/...` 또는 `linkedin.com/company/...` 패턴 검사 |

각 항목 통과 시 1점 → 합계 0~4점.

---

## 2. 4가지 버킷으로 분류

점수에 따라 한눈에 알 수 있도록 색상 뱃지로 표시:

| 버킷 | 점수 | 표시 | 의미 |
|---|---|---|---|
| **통과** | 4점 | ✅ 초록 | 4개 항목 전부 정상. 데이터 품질 양호 |
| **의심** | 2~3점 | ⚠ 노랑 | 일부 항목 실패. 사람 검토 필요 |
| **무효** | 0~1점 | ❌ 빨강 | 다수 실패. 데이터 보정 또는 삭제 검토 |
| **미검증** | — | ⏳ 회색 | 아직 자동 검증을 돌리지 않은 리드 |

> 점수가 낮다고 "그 업체가 가짜다"는 아닙니다. **데이터 입력에 빈칸/오타가 있거나, 우리가 가진 정보가 불완전하다**는 신호로 보시면 됩니다.

---

## 3. 어떤 케이스가 의심으로 걸리나 (실제 예)

### 이메일 실패 (`emailValid: false`)
- **syntax**: `okan@distributiongroup,com.tr` (콤마 오타)
- **no-mx**: `info@example-old-co.com` — 회사가 폐업 등으로 메일 도메인이 더 이상 메일 받지 않음
- **disposable**: `buyer@mailinator.com` — 일회용 메일

### 웹사이트 실패 (`websiteAlive: false`)
- 도메인 만료 / DNS 해석 실패
- 6초 타임아웃 (서버가 죽었거나 매우 느림)
- HTTP 404 / 5xx

### 전화 불일치 (`phoneMatch: false`)
- `Country: UAE` 인데 `Phone: +82-10-...` (한국 번호)
- `Country: Germany` 인데 `Phone: 0044 20 ...` (영국 번호)
- 컬럼 입력 실수 또는 담당자가 다른 나라에 거주

### LinkedIn 형식 오류 (`linkedinValid: false`)
- `https://www.linkedin.com/distrubution-group/` — `/company/` 또는 `/in/` 누락
- 일반 텍스트로 회사명만 적힌 경우

## 4. 사용 흐름

```
[1] CSV 임포트 → 800건 등록
[2] 🔍 검증 버튼 클릭 → 미검증 800건
[3] "검증 시작" → 30건씩 청크 처리 (병렬 4가지 체크)
    예상 소요: 1~3분 (DNS + HTTP 응답에 좌우됨)
[4] 결과: ✅ 312건 / ⚠ 287건 / ❌ 201건
[5] 툴바 [검증] 드롭다운에서 "⚠ 의심" 선택
    → 287건만 테이블에 표시 → 한 행씩 클릭해서 상세 확인
```

각 리드 행에 뱃지가 보이므로 어떤 리드가 어느 버킷인지 한눈에 식별 가능.

## 5. 현재 한계 (정직한 설명)

| 한계 | 영향 | 보완 방안 |
|---|---|---|
| **MX 레코드만 봄** — 실제 메일박스 존재 확인은 안 함 | "도메인은 살아있지만 그 이메일 계정은 없음"은 통과로 표시 | Hunter.io / NeverBounce 같은 유료 SMTP 검증 도입 |
| **사이트 alive ≠ 실제 회사 운영** | 도메인 파킹 페이지도 200으로 응답 | HTML 본문 분석 + LLM 판단 (Claude API) |
| **국가코드 매칭만 함** | 형식 자체가 잘못된 번호는 검출 못 함 | libphonenumber 라이브러리 도입 |
| **LinkedIn URL 형식만 검사** | 실제 페이지 존재 확인은 안 함 (LinkedIn 봇 차단) | 별도 LinkedIn API 또는 수동 검증 |
| **"이 업체가 K-beauty 바이어 맞나"는 판단 불가** | 도메인 검증만 함 — 사업 정합성은 못 봄 | **Claude API 통합 (Phase 2)** |

## 6. Phase 2 — LLM 기반 검증 (Claude API)

현재 검증은 "기술적 정합성"만 봅니다. Claude API를 추가하면 **"사업적 적합성"** 까지 판단 가능:

- 회사명 + 웹사이트 + BrandsChannels 컬럼을 LLM에 입력
- "이 업체가 한국 화장품(K-beauty) 바이어 / 디스트리뷰터로 보이는가?" 판단
- 담당자 이름·직책이 회사와 자연스러운 매칭인지 검토
- `Evidence` / `notes` 안의 정보 모순 검출

API 토큰이 충전돼 있으시면 다음 단계로 추가 가능합니다.

## 7. 기술 스택 요약

- **백엔드**: Next.js Route Handler (`/api/leads/verify`), MongoDB bulkWrite, Node.js dns/fetch 표준 모듈만 사용
- **프론트엔드**: 청크 단위(30건씩) 반복 호출 + progress bar
- **DB 저장**: 각 리드의 `verification` 서브도큐먼트 (재검증 시 덮어쓰기)
- **외부 의존성**: 없음 (자체 호스팅 가능, 무료)
